# سنجش تطبیق صوتی

مجموعه‌ی رگرسیون برای موتور تطبیق. هر تغییری در `product-matcher.service.ts`
یا موتور تجزیه دادی، این را قبل و بعد اجرا کن — بدون عدد، «بهترش کردم» حدس است.

## اجرا

سرور باید بالا باشد. بعد در همین پوشه:

```bash
python3 benchmark.py
```

فایل‌های لازم (`token.txt`، `locb.txt`، `sid.txt`) باید کنارش باشند:
توکن ورود، بارکد یک لوکیشن، و شناسه‌ی یک شیفت باز.

## معنی ستون‌ها

| ستون | یعنی |
|---|---|
| دقیق | همان محصول دقیق در رتبه‌ی ۱ |
| هم‌قطعه | قطعه‌ی درست، برند دیگر — وقتی کارگر برند نگفته این درست است |
| قابل‌قبول | مجموع دو ستون بالا |
| در ۳ اول | محصول درست در سه پیشنهاد اول بود |

## آخرین نتیجه (۱۴۰۵/۰۵/۱۲)

۶۰۰ جست‌وجو روی ۱۰۰ محصول واقعی:

| شکل گفتار | دقیق | قابل‌قبول |
|---|---|---|
| نام کامل | ۸۷٪ | ۸۷٪ |
| نام کامل + تعداد | ۸۶٪ | ۸۷٪ |
| بدون برند | ۶۳٪ | ۷۰٪ |
| ارقام فارسی | ۶۴٪ | ۷۱٪ |
| کوتاه (۳ کلمه) | ۳۶٪ | ۴۱٪ |
| **مجموع** | **۶۶٪** | **۷۱٪** |

سه نتیجه:

1. **گفتن تعداد ضرری ندارد** (۸۷٪ در برابر ۸۷٪).
2. **ارقام فارسی درست کار می‌کند** (۷۱٪ در برابر ۷۰٪ حالت معادل).
3. **گفتن برند ۱۷ واحد دقت اضافه می‌کند** — مهم‌ترین نکته برای آموزش کارگر.

## چرا تأیید خودکار خاموش است

از ۷ موردی که خودکار تأیید شد، فقط ۵ تا درست بود — **دقت ۷۱٪**. یکی از
غلط‌ها با اطمینان ۱۰۰ ثبت شد:

```
گفته شد: شیلنگ بالارادیات کوئیک ساینا S پولاسا
ثبت شد : مجموعه شیلنگ هیدرولیک قوی تیباساینا کوئیک پولاسا
```

یک تپ اضافه چند ثانیه است؛ یک ثبت خودکارِ اشتباه موجودی را خراب می‌کند و تا
انبارگردانی بعدی پیدا نمی‌شود. کلید در `AUTO_CONFIRM_ENABLED` است — وقتی دقتش
به ۹۵٪+ رسید روشنش کن.

## بهترش کردن

نمونه‌ی فعلی از کاتالوگ به‌صورت تصادفی گرفته شده. برای تنظیم واقعی، عبارت‌های
**واقعی کارگرها** را جمع کن (چه گفتند و کدام کالا درست بود) و جای
`sample-100.txt` بگذار. آن‌وقت می‌شود آستانه‌ها را با داده تنظیم کرد نه با حدس.
