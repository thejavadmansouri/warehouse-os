# جداسازی سایت از مغازه (دو ماشین)

این سند توضیح می‌دهد چرا سایتِ فروشگاه اینترنتی از پنلِ مغازه جدا شد و چطور هر
دو سمت اجرا و deploy می‌شوند.

## اصل

- **سیستمِ مغازه (POS، موجودی، فروش، کاربران، بکاپ) سکرت و لوکال است.** فقط روی
  شبکه‌ی داخلی (LAN) اجرا می‌شود و هیچ endpointی از آن روی اینترنت نیست.
- **سایت عمومی است.** روی VPS اجرا می‌شود و با مغازه **فقط از طریق API** حرف
  می‌زند — نه دیتابیس مشترک، نه دسترسی مستقیم.
- کدِ مغازه دست نمی‌خورد؛ `apps/site` با کپیِ الگو از `apps/web` ساخته شده.

## دو نقشِ بک‌اند

یک کدبیس (`apps/api`) روی دو ماشین اجرا می‌شود:

| نقش | متغیر | چه چیزی لود می‌شود |
|---|---|---|
| انبار | `APP_ROLE=warehouse` (پیش‌فرض) | همه‌چیز: POS، موجودی، فروش، کاربران، بکاپ، `OnlineOrdersModule` (صفِ تحویل) |
| سایت | `APP_ROLE=site` | فقط `StorefrontModule` (کاتالوگ/سفارش عمومی)، `SiteAdminModule` (مدیریت محتوا)، `AuthModule` |

مرز در `apps/api/src/app.module.ts` است: `WAREHOUSE_ONLY` فهرست ماژول‌هایی است که
هرگز روی سرورِ اینترنتی لود نمی‌شوند. اگر ماژول جدیدی ساختید و به انبار مربوط
است، آن را همان‌جا بگذارید.

## اتصال بین دو ماشین — سینک

اتصال فقط از طریق endpoint های `/sync/*` با کلیدِ مشترکِ `SYNC_SECRET` است:

- **انبار → سایت:** کاتالوگ (کالاهای `showOnline` با قیمت/موجودی) و تنظیمات
  فروشگاه به سایت **پوش** می‌شود (`sync-agent.service.ts` → `POST /sync/catalog`).
- **سایت → انبار:** سفارش‌های ثبت‌شده روی سایت را انبار **پول** می‌کند
  (`GET /sync/orders`) و وضعیتِ تحویل را برمی‌گرداند (`POST /sync/orders/status`).
- ایجنتِ سینک فقط روی سمتِ انبار اجرا می‌شود (`SYNC_ROLE=warehouse`)؛ سمتِ سایت
  فقط دریافت‌کننده است (`SYNC_ROLE=site`). سایت هرگز آدرس یا دیتابیسِ انبار را
  نمی‌داند.

نقشِ سینک مستقل از نقشِ اپ است:

```bash
# روی سرورِ انبار:
APP_ROLE=warehouse SYNC_ROLE=warehouse SITE_URL=https://shop.example.com SYNC_SECRET=... node dist/main

# روی VPS (سایت):
APP_ROLE=site SYNC_ROLE=site SYNC_SECRET=... node dist/main
```

## ساختار اپ‌ها

| اپ | محتوا | به چه API وصل است |
|---|---|---|
| `apps/web` | پنلِ مغازه: POS، موجودی، مشتریان، اسناد، گزارش‌ها، صفِ تحویلِ سفارش‌های آنلاین | API انبار (`APP_ROLE=warehouse`) |
| `apps/site` | سایتِ عمومی (`/shop/*`) + پنلِ مدیریتِ محتوا (`/admin/*`) | API سایت (`APP_ROLE=site`) |

صفحه‌های قدیمیِ سایت داخل `apps/web` (زیر `/shop` و `/admin/site`) هنوز روی دیسک
هستند و با آدرس مستقیم باز می‌شوند، ولی از منوی پنلِ مغازه برداشته شده‌اند.

### `apps/site` — چه چیزی دارد

- **سایتِ عمومی:** کاتالوگ، جزئیات کالا، سبد خرید، ورودِ OTP، سفارش، حسابِ مشتری
  (کپی از `apps/web/src/app/shop`).
- **پنلِ مدیرِ سایت:** لاگین (`/admin/login`)، نمای کلی، سفارش‌های فقط‌خواندنی،
  کوپن، بنر، نظرات (تأیید/رد)، مناطق ارسال، اعلانِ موجودی، سئو.
- کلاینتِ API (`apps/site/src/lib/api.ts`) فقط endpoint های سایت را صدا می‌زند و
  توکنِ مدیرِ سایت را می‌فرستد — هیچ تابعِ انباری (POS، موجودی، …) ندارد.

## اجرای توسعه

### راه‌اندازیِ API سایت (برای دیدن پنلِ سایت)

در حالت dev، API با نقشِ پیش‌فرض (`warehouse`) بالا می‌آید و endpoint های
سایت-ادمین (`/coupons`, `/site-admin/*`) را ندارد. برای دیدن پنلِ سایت، API را
با نقشِ سایت روی یک پورتِ جدا بالا بیاورید:

```bash
# ترمینال ۱ — API سایت روی پورت 3010 (به همان دیتابیس dev وصل می‌شود)
cd apps/api
APP_ROLE=site PORT=3010 npm run start:dev
```

```bash
# ترمینال ۲ — اپِ سایت
cd apps/site
NEXT_PUBLIC_SITE_API_PORT=3010 npm run dev   # پورت پیش‌فرض 3002
```

> توجه: برای login به پنلِ سایت، یک کاربرِ با `canManageSite=true` لازم است.
> در دیتابیس dev معمولاً کاربرِ `admin` (نقش ADMIN) این پرچم را دارد.

### راه‌اندازیِ کاملِ مغازه (بدون سایت)

```bash
npm run dev:api    # پورت 3000 — نقشِ انبار
npm run dev:web    # پورت 3001 — پنلِ مغازه
```

## ساخت و deploy

```bash
# API (هر دو نقش یک build دارند؛ نقش با env مشخص می‌شود)
npm run build:api

# اپِ سایت
cd apps/site && npm run build

# پنلِ مغازه
cd apps/web && npm run build
```

### VPS (سایت)

1. `apps/api` را build و روی VPS با `APP_ROLE=site SYNC_ROLE=site` اجرا کنید.
2. `apps/site` را build و با `next start` روی همان VPS اجرا کنید.
3. `SYNC_SECRET` (حداقل ۳۲ کاراکتر) را در `.env` هر دو ماشین بگذارید.
4. در تنظیماتِ انبار (`/admin/shop-settings`) کلیدِ «فروشگاه روشن» را بزنید؛
   ایجنتِ سینک کاتالوگ را به سایت می‌فرستد.

### سرورِ انبار

`apps/api` را با `APP_ROLE=warehouse SYNC_ROLE=warehouse SITE_URL=<آدرس سایت>`
اجرا کنید. ایجنتِ سینک به‌صورت زمان‌بندی‌شده کاتالوگ را پوش و سفارش‌ها را پول
می‌کند؛ فروشنده صفِ تحویل را از پنلِ مغازه (`/admin/online-orders`) مدیریت
می‌کند.

## امنیت

- ماژول‌های انبار فقط با `APP_ROLE=warehouse` لود می‌شوند؛ روی VPS اصلاً در
  باینری نیستند.
- `SyncAuthGuard` همه‌ی `/sync/*` را با مقایسه‌ی زمان‌ثابتِ `SYNC_SECRET` محافظت
  می‌کند و این مسیرها هرگز CORS ندارند.
- `apps/site` فقط endpoint های عمومیِ `/shop/*` و endpoint های گاردشده‌ی
  سایت-ادمین را صدا می‌زند؛ کلاینتش هیچ تابعِ انباری ندارد.
