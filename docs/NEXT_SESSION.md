# وضعیت فعلی و کار بعدی

**تاریخ:** ۱۴۰۵/۰۵/۱۴ · شاخه: `feat/android-operator-epic0` (۶۰+ کامیت جلوتر از `origin/main`)

## ⛔ اولین کاری که باید انجام شود

**اسکریپت‌های PowerShell روی ویندوز اجرا نمی‌شوند — خطای پارس.**

`deploy/windows/*.ps1` کامنت و پیام فارسی دارند و UTF-8 بدون BOM ذخیره شده‌اند.
Windows PowerShell 5.1 فایل `.ps1` را با codepage محلی ویندوز می‌خواند نه UTF-8،
پس متن فارسی خراب می‌شود و همان بایت‌های خراب پارسر را می‌شکنند.

خطای واقعی کاربر:

```

+ ... ¨Ø§ Node $REQUIRED_NODE_MAJOR Ø³Ø§Ø®ØªÙ‡ ...

```

**راه‌حل انتخاب‌شده (هنوز اعمال نشده):** `build.ps1`، `first-run.ps1` و
`services.ps1` **کاملاً ASCII** بازنویسی شوند — کامنت و پیام‌ها انگلیسی. اینها
ابزار توسعه‌اند نه رابط کاربر، و خروجی فارسی در کنسول ویندوز به‌هرحال خوانا نیست.
`installer.iss` هم برای اطمینان ASCII شود. فارسی فقط در `README.md` بماند.

(BOM هم جواب می‌دهد ولی شکننده است: هر ویرایشگری که BOM را بردارد دوباره می‌شکند.)

## آنچه در این جلسه انجام و **تأیید** شد

هر کدام با تست واقعی، نه فرض:

- **کرش لاگین اندروید** — `HttpUrl.Builder.scheme("ws")` استثنا پرت می‌کرد. با jar
  واقعی پروژه بازتولید و رفع شد.
- **push کار برداشت** — گیت‌وی `payload.userId` می‌خواند ولی توکن `sub` دارد. هر ۶
  کار برداشت روی گوشی A12s تیک خورد.
- **کلید امضای توکن** — رشته‌ی ثابت داخل سورس و در `.env` هم ست نشده بود. حالا هر
  نصب کلید خودش را دارد و سرور بدون آن بالا نمی‌آید. توکن جعلی با کلید قدیمی ۴۰۱.
- **اپ `.env` را در زمان اجرا نمی‌خواند** — فقط تصادفاً از طریق Prisma کار می‌کرد.
  حالا `load-env.ts` صریح می‌خواند و `WOS_ENV_FILE` را هم می‌پذیرد (تست‌شده).
- **تبدیل پیش‌فاکتور** — فروش نسیه را «نقد دریافت شد» ثبت می‌کرد و بدهی مشتری
  ناپدید می‌شد.
- **تخفیف** — ردیفی و فاکتوری، تومان و درصد. مقابل سرور تست شد: ۱۴۰٬۰۰۰ → ۱۳۵٬۰۰۰.
- **قیمت‌گذاری** — تکی/گروهی/برندی با dry-run، روی برند واقعی تست شد.
- **یادگیری قیمت از فروش** — قیمتی که فروشنده می‌زند قیمت کالا می‌شود (۴ سناریو).
- **فروش کالای ثبت‌نشده** — بررسی موجودی از مسیر فروش برداشته شد؛ ردیف بدون قفسه
  روی مکان سیستمی «موجودی ثبت‌نشده» (عمق ۹۹) منفی می‌شود. برداشت انباردار (`OUT`)
  همچنان محدود است — جدا تست شد.
- **نشست تک‌دستگاهه** — آخرین ورود برنده؛ دستگاه اول `SESSION_REPLACED`.
- **نقش‌ها** — فرود نقش‌محور + **۶ کنترلر بدون گارد** بسته شد (ایمپورت اکسل، ساخت
  برند، تولید موقعیت… هر کاربر لاگین‌شده می‌توانست).
- **چاپ لیبل TSPL** — Puppeteer حذف شد (۵۶۳MB Chromium). بارکد را پرینتر می‌کشد،
  نام فارسی با `sharp` رَستر می‌شود (شکل‌دهی بصری تأیید شد).
- **آدرس API از build درآمد** — تأیید: صفحه از `10.141.233.130:3001` → API روی
  همان میزبان.
- **تست بار** — ۵۰۰ کالا، ۴۰ فاکتور در ۱.۹ ثانیه (میانه ۴۷ms)، دفتر خواند.

## کار بعدی، به ترتیب

۱. **رفع encoding اسکریپت‌های PowerShell** (بالا). بدون این هیچ نصب‌کننده‌ای ساخته
   نمی‌شود.
۲. **اجرای `build.ps1` روی لپ‌تاپ ویندوزی** و رفع خطاهای اولش — این اسکریپت‌ها
   **هرگز روی ویندوز اجرا نشده‌اند**.
۳. **تست پنل روی ویندوز ۷ با Chrome 109.** آخرین کروم سازگار ۱۰۹ است و Next.js 16
   پیش‌فرض برای جدیدتر خروجی می‌دهد. اگر صفحه سفید شد، `browserslist` روی ۱۰۹ پین
   و وب دوباره build شود.
۴. **تست چاپ روی پرینتر TSC واقعی.** خروجی TSPL بایت‌به‌بایت بررسی شده ولی هرگز
   روی پرینتر نرفته. اول نام پرینتر در تنظیمات لیبل وارد شود.
۵. **بکاپ روی درایو دوم** با انتخاب مسیر توسط کاربر. فعلاً بدون رمز (تصمیم کاربر).

## نکته‌های پایدار

- `next build` **تایپ‌چک نمی‌کند** (`ignoreBuildErrors: true`). `tsc --noEmit` جدا.
- Node 24 (ABI 137) و Postgres 18.4 — نسخه‌ی بسته‌بندی باید همین باشد، نه قدیمی‌تر.
- شاخه روی GitHub **push نشده**؛ remote روی HTTPS است و در محیط غیرتعاملی منتظر
  اعتبارنامه می‌ماند. باید از ترمینال خود کاربر زده شود.
- کنارگذاشته‌شده به‌خواست کاربر: مدیریت موقعیت‌ها، کارت‌خوان (پارسیان روی شبکه —
  نیاز به پروتکل ECR بانک)، حذف قلم از فاکتور ثبت‌شده.
