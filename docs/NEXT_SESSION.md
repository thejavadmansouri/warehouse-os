# وضعیت فعلی و کار بعدی

**تاریخ:** ۱۴۰۵/۰۵/۱۴ · شاخه: `feat/android-operator-epic0` (۶۰+ کامیت جلوتر از `origin/main`)

---

## ✅ بلوکر encoding رفع شد

هر چهار فایل `deploy/windows/` بازنویسی شدند: **ASCII خالص، بدون BOM** — تأیید
بایت‌به‌بایت (بالاترین بایت هر فایل `0x7d`). فارسی فقط در `README.md` ماند؛
اسم میان‌برهایی که مشتری می‌بیند در `first-run.ps1` از روی code point ساخته
می‌شود.

قانون از این به بعد در `deploy/windows/README.md` نوشته شده. بررسی قبل از کامیت:

```bash
LC_ALL=C grep -n '[^[:print:][:space:]]' deploy/windows/*.ps1 deploy/windows/*.iss
```

**ولی موقع بازنویسی پنج اشکال دیگر پیدا شد که هرکدام به‌تنهایی نصب را
می‌شکستند** — همه رفع شدند:

۱. **CLI پریزما اصلاً داخل بسته نمی‌رفت.** `prisma` devDependency ریشه است و در
   `apps/api/package.json` نیست، پس `npm install --omit=dev` نمی‌آوردش. یعنی
   `first-run.ps1` سرِ مشتری روی `migrate deploy` می‌مرد. حالا build همان نسخه‌ی
   نصب‌شده را داخل بسته می‌گذارد و وجود فایلش را چک می‌کند.

۲. **پنل وب اصلاً بالا نمی‌آمد.** خروجی standalone نکست `node_modules` را در دو
   سطح پخش می‌کند و **خودِ `next` در سطحی است که build کپی نمی‌کرد**. حالا کل
   درخت کپی می‌شود و یک `server.js` واسط در مسیر ثابت ساخته می‌شود.

۳. **`.env` با BOM نوشته می‌شد.** در PowerShell 5.1 معنی `-Encoding utf8` یعنی
   «با BOM»، و آن سه بایت به اسم اولین کلید می‌چسبند. تست شد: با BOM مقدار
   `DATABASE_URL` برابر `undefined` است — یعنی API بالا نمی‌آمد. حالا ASCII.

۴. **بکاپ شبانه هر شب شکست می‌خورد.** `PG_DUMP_PATH` ست نمی‌شد و `pg_dump` روی
   ویندوز روی PATH نیست؛ ضمناً مقصد پیش‌فرض برنامه `...\backup` بود ولی
   نصب‌کننده `...\backups` می‌ساخت. حالا هر دو مسیر در `.env` ست می‌شوند و مقصد
   موقع نصب در دیتابیس تثبیت می‌شود (`ON CONFLICT DO NOTHING`، تا انتخاب بعدیِ
   مدیر بازنویسی نشود).

۵. **سرویس دیتابیس هرگز بالا نمی‌آمد.** پستگرس روی ویندوز زیر حساب مدیر اجرا
   نمی‌شود (`check_root()` → `pgwin32_is_admin()` → `exit(1)`؛ از سورس پستگرس ۱۸
   تأیید شد) و حساب پیش‌فرض سرویس در NSSM یعنی LocalSystem **عضو Administrators
   است**. ضمناً `pg_ctl` موقتِ داخل `first-run.ps1` هم چون elevated بود به همان
   منع می‌خورد. حالا سرویس با `NT AUTHORITY\NetworkService` اجرا می‌شود، پوشه‌ی
   `data` با SID به همان حساب داده می‌شود، و به‌جای اجرای موقت، خودِ سرویس زودتر
   ثبت و روشن می‌شود (`services.ps1 -DbOnly`). `initdb` این محدودیت را ندارد.

اضافه هم شد: توقف سرویس‌ها **قبل از** کپی فایل‌ها (وگرنه نصب دوباره روی نصب
زنده به‌خاطر فایل قفل‌شده شکست می‌خورد)، بررسی سلامت در پایان نصب،
`INSTALL-INFO.txt` و `data\install.log` (چون پنجره‌ی نصب بسته می‌شود و کسی
پیام‌ها را نمی‌خواند)، و بررسی major پستگرس در `build.ps1`.

یک اصلاح در سورس API هم لازم شد: `main.ts` پورت را هاردکد ۳۰۰۰ کرده بود و
`PORT` سرویس را نادیده می‌گرفت — یعنی پورتی که نصب‌کننده روی فایروال باز می‌کرد
می‌توانست به جایی نرسد. حالا `PORT` خوانده می‌شود و روی `0.0.0.0` گوش می‌دهد
(با `PORT=3999` واقعاً تست شد).

## آنچه در این جلسه انجام و **تأیید** شد

هر کدام با تست واقعی، نه فرض:

- **کرش لاگین اندروید** — `HttpUrl.Builder.scheme("ws")` استثنا پرت می‌کرد. با jar
  واقعی پروژه بازتولید و رفع شد.
- **push کار برداشت** — گیت‌وی `payload.userId` می‌خواند ولی توکن `sub` دارد. هر ۶
  کار برداشت روی گوشی A12s تیک خورد.
- **کلید امضای توکن** — رشته‌ی ثابت داخل سورس و در `.env` هم ست نشده بود. حالا هر
  نصب کلید خودش را دارد و سرور بدون آن بالا نمی‌آید. توکن جعلی با کلید قدیمی ۴۰۱.
- **اپ `.env` را در زمان اجرا نمی‌خواند** — فقط تصادفاً از طریق Prisma کار می‌کرد.
  حالا `load-env.ts` صریح می‌خواند و `WOS_ENV_FILE` را هم می‌پذیرد (تست‌شده).
- **تبدیل پیش‌فاکتور** — فروش نسیه را «نقد دریافت شد» ثبت می‌کرد و بدهی مشتری
  ناپدید می‌شد.
- **تخفیف** — ردیفی و فاکتوری، تومان و درصد. مقابل سرور تست شد: ۱۴۰٬۰۰۰ → ۱۳۵٬۰۰۰.
- **قیمت‌گذاری** — تکی/گروهی/برندی با dry-run، روی برند واقعی تست شد.
- **یادگیری قیمت از فروش** — قیمتی که فروشنده می‌زند قیمت کالا می‌شود (۴ سناریو).
- **فروش کالای ثبت‌نشده** — بررسی موجودی از مسیر فروش برداشته شد؛ ردیف بدون قفسه
  روی مکان سیستمی «موجودی ثبت‌نشده» (عمق ۹۹) منفی می‌شود. برداشت انباردار (`OUT`)
  همچنان محدود است — جدا تست شد.
- **نشست تک‌دستگاهه** — آخرین ورود برنده؛ دستگاه اول `SESSION_REPLACED`.
- **نقش‌ها** — فرود نقش‌محور + **۶ کنترلر بدون گارد** بسته شد (ایمپورت اکسل، ساخت
  برند، تولید موقعیت… هر کاربر لاگین‌شده می‌توانست).
- **چاپ لیبل TSPL** — Puppeteer حذف شد (۵۶۳MB Chromium). بارکد را پرینتر می‌کشد،
  نام فارسی با `sharp` رَستر می‌شود (شکل‌دهی بصری تأیید شد).
- **آدرس API از build درآمد** — تأیید: صفحه از `10.141.233.130:3001` → API روی
  همان میزبان.
- **تست بار** — ۵۰۰ کالا، ۴۰ فاکتور در ۱.۹ ثانیه (میانه ۴۷ms)، دفتر خواند.

## کار بعدی، به ترتیب

۱. **اجرای `build.ps1` روی لپ‌تاپ ویندوزی.** این اسکریپت‌ها هنوز **هرگز روی
   ویندوز اجرا نشده‌اند** — چیزی که روی مک قابل تست نبود. آنچه تست شد: ASCII
   بودن، ساختار و نحو ۵.۱، قالب `.env` روی نود ۲۴، و SQL روی اسکیمای واقعی.
   انتظار داشته باش چند مسیر یا پرچم اصلاح شود.
۲. **نصب کامل روی خود لپ‌تاپ، نه سرور مشتری.** بعدش:
   - ری‌استارت سخت بزن و ببین هر سه سرویس خودشان بالا می‌آیند.
   - یک شب صبر کن (یا ساعت بکاپ را جلو بیاور) و ببین دامپ در `backups\` ساخته
     می‌شود.
   - **یک بازیابی واقعی تست کن** و زمانش را یادداشت کن.
۳. **تست پنل روی ویندوز ۷ با Chrome 109.** آخرین کروم سازگار ۱۰۹ است و Next.js 16
   پیش‌فرض برای جدیدتر خروجی می‌دهد. اگر صفحه سفید شد، `browserslist` روی ۱۰۹ پین
   و وب دوباره build شود.
۴. **کپی بکاپ روی درایو دوم.** بکاپ روی همان دیسکِ دیتابیس بکاپ نیست. مسیر را
   کاربر انتخاب کند. فعلاً بدون رمز (تصمیم کاربر).
۵. **تست چاپ روی پرینتر TSC واقعی.** خروجی TSPL بایت‌به‌بایت بررسی شده ولی هرگز
   روی پرینتر نرفته. اول نام پرینتر در تنظیمات لیبل وارد شود.

بعدتر، نه امشب: بکاپ خودکار به‌عنوان قدم اول نصب‌کننده؛ جداکردن نقش دیتابیس از
`postgres`؛ HTTPS.

  وای‌فای.

## نکته‌های پایدار

- `next build` **تایپ‌چک نمی‌کند** (`ignoreBuildErrors: true`). `tsc --noEmit` جدا.
- Node 24 (ABI 137) و Postgres 18.4 — نسخه‌ی بسته‌بندی باید همین باشد، نه قدیمی‌تر.
- شاخه روی GitHub **push نشده**؛ remote روی HTTPS است و در محیط غیرتعاملی منتظر
  اعتبارنامه می‌ماند. باید از ترمینال خود کاربر زده شود.
- کنارگذاشته‌شده به‌خواست کاربر: مدیریت موقعیت‌ها، کارت‌خوان (پارسیان روی شبکه —
  نیاز به پروتکل ECR بانک)، حذف قلم از فاکتور ثبت‌شده.
