# پرامپت: یکدست‌سازی الگوی فهرست‌ها و بازطراحی دفتر روزنامه (کارو / Warehouse OS)

این پرامپت رو مستقیم به Claude بفرستی. هدف اینه که دو مورد اول گزارش بررسی UI/UX رو دقیق و با کمترین ریسک انجام بده.

## زمینه پروژه
- نام: کارو / Kardoo / Warehouse OS
- مسیر ریشه: `C:\warehouse-os`
- استک: Next.js 15 (App Router) + TypeScript + Tailwind CSS v4 + shadcn/ui + React Query + NestJS API + Prisma + PostgreSQL
- زبان رابط: فارسی (RTL)
- قوانین حیاتی:
  - موجودی فقط داخل `Inventory` ذخیره میشه
  - `Product` هیچ `quantity` نداره
  - هر تغییر موجودی فقط از `InventoryOperation` انجام میشه
  - هر عملیات باید `InventoryLog` تولید کنه
  - حذف‌ها `Soft Delete` هستن
  - برای API حتماً از `@/lib/api.ts` استفاده شه (هیچ‌جا مستقیم `fetch` نزنه)

## هدف کار
دو اصلاح موازی ولی مرتبط انجام شه:

### مورد ۱: یکدست‌سازی الگوی فهرست‌ها (List Pattern Unification)
صفحات فهرست باید یه الگوی کاملاً یکسان داشته باشن:

- **استفاده از کامپوننت واحد**: همه جداول باید از `@/components/ui/table.tsx` استفاده کنن. دیگه نباید از `TH/TD` دستی مثل `customers/page.tsx` یا الگوهای پراکنده استفاده شه.
- **هدر ثابت (sticky header)**: برای جدول‌های با بیش از ~۱۰ ردیف، `TableHead` باید `sticky top-0 z-10 bg-background/95 backdrop-blur` بگیره تا موقع اسکرول هدر گم نشه.
- **نوار ابزار یکدست**: فیلترها، جست‌وجو، دکمه‌های اصلی و ثانویه باید توی یه نوار تمیز جمع بشن. اکشن‌های کم‌استفاده (مثل CSV Export) داخل منوی `...` با `DropdownMenu` بیاد.
- **فیلترهای فعال**: اگه فیلتر فعال باشه، به‌صورت `Chip/Badge` نشون داده شه و هر چیپ بتونه جداگانه حذف شه.
- **Pagination یکدست**: باید از کامپوننت موجود `@/components/data-table-pagination.tsx` استفاده شه. اگه کامپوننت دیگه‌ای هست ولی یکدست نیست، تطبیق بدی.
- **EmptyState/LoadingState/ErrorState**: از `@/components/states.tsx` استفاده شه و همه صفحات همین الگو رو رعایت کنن.
- **تراکم خوانا**: `TableCell` و `TableRow` باید خوانا باشن. افزایش جزئی `py-2` بهتر از فشردگی افراطیه. از `whitespace-nowrap` فقط جایی استفاده شه که واقعاً لازم باشه.
- **عددها**: هر جا عدد مالی/تعداد هست باید `tabular-nums` اعمال شه.
- **RTL تراز**: هدرها با `text-start` تراز بشن و ستون‌های عددی طوری تراز بشن که با مقادیرشان هماهنگ باشن.

**صفحات هدف برای یکدست‌سازی:**
- `apps/web/src/app/admin/customers/page.tsx` (بسیار فشرده، از TH/TD دستی استفاده شده)
- `apps/web/src/app/admin/products/page.tsx` (دکمه‌های زیاد، فیلترهای پراکنده)
- `apps/web/src/app/admin/purchases/page.tsx` (نسبتاً تمیز ولی تطبیق با الگوی یکدست لازمه)
- `apps/web/src/app/admin/invoices/page.tsx` (قابل توجه، داخل `InvoicesPanel` هست)
- `apps/web/src/app/admin/documents/page.tsx` (میزبان تب‌هاست، باید اطمینان حاصل شه تغییری نداده شه)
- `apps/web/src/app/admin/returns/page.tsx`, `apps/web/src/app/admin/receipts/page.tsx`, `apps/web/src/app/admin/payouts/page.tsx` (اگه داخل تب‌های اسناد هستن)
- `apps/web/src/app/admin/suppliers/page.tsx`
- `apps/web/src/app/admin/reports/page.tsx` (فقط بخش‌های جدول‌دارش)

**اصل مهم:** هیچ تغییری توی منطق کسب‌وکار، API calls، Query keys، Role checks، Keyboard shortcuts نده. فقط **ساختار UI، کلاس‌ها، کامپوننت‌بندی و چیدمان** رو اصلاح کن.

### مورد ۲: بازطراحی دفتر روزنامه (General Ledger / Vouchers)
صفحه `apps/web/src/app/admin/vouchers/page.tsx` و کامپوننت `@/components/voucher-card.tsx` رو طوری بازطراحی کن که **حس واقعی دفتر روزنامه حسابداری** بده.

**هدف طراحی:**
- **فرمت جدول‌محور**: بجای کارت‌های عمودی تک‌تک، از جدول استاندارد استفاده شه با ستون‌های زیر:
  1. `ردیف` (شماره ترتیبی صفحه)
  2. `تاریخ` (شماره فارسی با `tabular-nums`)
  3. `شماره سند` (لینک‌دار اگه بشه به سند مبدا بره)
  4. `نوع سند` (با برچسب خوانا)
  5. `شرح` (خلاصه عملیات)
  6. `طرف حساب / مرجع` (مشتری/تأمین‌کننده/عمومی)
  7. `بدهکار` (مبلغ با `tabular-nums`, تراز راست)
  8. `بستانکار` (مبلغ با `tabular-nums`, تراز راست)
- **جمع کل پایین جدول**: ردیف `tfoot` یا نوار چسبنده پایین با `جمع کل بدهکار`، `جمع کل بستانکار`، `تراز` (باید برابر بشن یا نشون داده شه)
- **فیلترهای یکدست**: فیلتر `نوع سند`، `از تاریخ`، `تا تاریخ` باید توی نوار فیلتر تمیز جمع بشن (مشابه الگوی مورد ۱)
- **رفتن به سند مبدا**: اگه سند قابل رفرنس داره (فاکتور فروش/خرید/دریافت/پرداخت/مرجوعی/ابطال)، بتونه با کلیک روی `شماره سند` یا دکمه کوچک، به صفحه مربوطه بره
- **خوانایی**: از رنگ‌های کم‌اشباع استفاده شه. `بدهکار` معمولاً با متن معمولی، `بستانکار` هم با متن معمولی نشون داده شه (نباید رنگ‌های تند زیاد استفاده شه). فقط اگه میشه از تمهیدهای ظریف کمک بگیری.
- **حالت خالی و بارگذاری**: از `EmptyState`، `LoadingState`، `ErrorState` استفاده شه
- **Pagination**: از `DataTablePagination` استفاده شه
- **دسترسی**: فقط `ADMIN` و `MANAGER` بتونن ببینن (همین الان هم همینجوریه، حفظ شه)

**نکات:**
- نیازی نیست کل ساختار API عوض شه. اگه فیلدهای لازم برای لینک به سند مبدا توی `Voucher` نباشه، با کمترین تغییر ممکن بررسی کن و اگه شد اضافه کن، وگرنه فقط `شماره سند` و `نوع سند` نشون بده
- کامپوننت `voucher-card.tsx` رو میشه حذف یا نگه داشت ولی دیگه استفاده نشه. ترجیح اینه که کد تمیزتر شه
- نباید منطق حسابداری (محاسبات بدهکار/بستانکار) دست بزنی. فقط نمایش و چیدمان رو عوض کن

## قوانین اجرا
- **کمترین تغییر**: فقط همون چیزهایی که گفته شده رو اصلاح کن. هیچ رفرکتور بزرگ بی‌ربط نکن
- **حفظ رفتار**: کیبورد شورتکات‌ها، role guard، query cache، toast، dialog ها دست‌نخورده بمونن
- **RTL اولویت**: همه چیز کاملاً راست‌چین و هماهنگ با تم فعلی باشه
- **TypeScript تمیز**: هیچ `any` جدید اضافه نکن. از تایپ‌های موجود استفاده کن
- **استفاده از کامپوننت‌های موجود**: اول `@/components/ui/*`، `states.tsx`, `data-table-pagination.tsx` رو بررسی کن و ازشون استفاده کن
- **ریسپانسیو**: روی دسکتاپ اولویت داره (پیشخوان مغازه)، ولی نباید توی موبایل کاملاً خراب شه
- **یکدست‌سازی تدریجی**: اگه صفحه‌ای خیلی بزرگه و نمیشه با یه بار تمومش کنی، میشه قدم‌به‌قدم انجام بدی ولی **هدف نهایی یکدست بودن همه صفحات ذکر شده** هست

## نحوه گزارش‌دهی
بعد از انجام کار، یه گزارش کوتاه و شفاف بنویس شامل:
- **فهرست فایل‌های تغییر یافته**
- **خلاصه تغییرات هر بخش**
- **بررسی سریع**: آیا الگوی جدول یکدست شده؟ آیا دفتر روزنامه به فرمت جدول تبدیل شده؟
- **ریسک‌ها / نکات باقی‌مانده** (اگه هست)
- **تست دستی پیشنهادی** (۲-۳ سناریو ساده برای چک کردن)

**شروع کن و فقط همون دو مورد رو انجام بده.** هیچ‌چیز اضافه برنمی‌گردونی.
